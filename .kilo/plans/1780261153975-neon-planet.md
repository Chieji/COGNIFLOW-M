## Plan Steps

### 1. Preparation
- Ensure we are in repository root: C:\Users\donpr\OneDrive\Documents\manus\COGNIFLOW-M
- Create review branch: `git checkout -b bug-review/auto/$(date +%Y%m%d%H%M%S)`
- Verify lockfile: package-lock.json exists (good)
- If node_modules missing or outdated, run `npm ci` (capture log to artifacts/install.log)
  - Else, note dependencies already installed.

### 2. Static Checks
- Type-check: `npx tsc --noEmit 2>&1 | tee artifacts/tsc.log`
- Lint: 
  - Check if eslint configured (look for .eslintrc, eslint in package.json devDependencies)
  - If not, install eslint temporarily: `npm install -D eslint@latest @typescript-eslint/parser@latest @typescript-eslint/eslint-plugin@latest eslint-plugin-react@latest eslint-plugin-react-hooks@latest`
  - Create a basic .eslintrc.json if missing (extend: ['eslint:recommended', 'plugin:@typescript-eslint/recommended', 'plugin:react/recommended', 'plugin:react-hooks/recommended'])
  - Run: `npx eslint . --ext .ts,.tsx,.js,.jsx 2>&1 | tee artifacts/eslint.log`
- Find TODO/FIXME, console.log, debugger:
  - `git grep -n --heading -e "TODO" -e "FIXME" -e "console.log" -e "debugger" > artifacts/todo_console_debugger.txt 2>/dev/null || true`
- Search for sensitive tokens or secrets (basic):
  - `git grep -n --heading -E "API_KEY|SECRET|PASSWORD|TOKEN|private_key" || true > artifacts/secret_search.txt 2>/dev/null || true`

### 3. Build & Bundle
- Run build: `npm run build 2>&1 | tee artifacts/build.log`
- If build fails, capture error and stop; categorize errors.
- If build succeeds, record dist file sizes: `ls -lh dist/ > artifacts/dist_sizes.txt`

### 4. Run Dev Server / Smoke Test
- Start dev server in background: `npm run dev > artifacts/dev-server.log 2>&1 &`
- Wait for server to start (e.g., 10 seconds), capture PID.
- Use a headless browser (if available) or manual checks:
  - Open http://localhost:5173 in browser (if not headless, note to open manually)
  - Capture console errors/warnings: save browser console log to artifacts/browser_console.log
  - Check network for 404s: save network log if possible
  - Take full-page screenshot: artifacts/screenshots/homepage.png (if headless available)
- Stop dev server after capture.

### 5. Runtime Behavioral Checks
- Manually test (or script if possible):
  - Login flow (if applicable)
  - Main screen navigation
  - Model playground (if exists)
  - Examples (if any)
  - File upload (if present)
  - Form submissions
- Record steps for any crash, UI block, wrong output in artifacts/runtime_issues.txt

### 6. Dependency & Security Checks
- Run npm audit: `npm audit --json > artifacts/npm_audit.json`
- Check for out-of-range/suspicious versions (review npm audit output)
- If high/critical vulnerabilities, note for remediation.

### 7. Accessibility Quick Checks
- Install axe-core if not present: `npm install -D axe-core`
- Run axe: `npx axe-core/cli http://localhost:5173 --output artifacts/axe_results.json` (if dev server still running) or use saved HTML.
- Check color contrast, missing alt text, missing form labels (from axe results).

### 8. Tests
- Check if tests exist (look for __tests__, *.test.*, vitest, jest config)
- If tests exist: run `npm test 2>&1 | tee artifacts/test.log`
- If none: note missing test coverage and suggest initial smoke tests (e.g., test App.jsx renders, basic interactions).

### 9. Coverage & Missing CI
- Check for GitHub Actions: `ls -la .github/workflows/`
- If missing, recommend adding CI workflow for lint, build, test.
- Also check for other CI (GitLab, AzureDevOps) but focus on GitHub.

### 10. Make Suggested Fixes
- For each small fix (e.g., removing console.log, fixing lint errors):
  - `git add <files>`
  - `git commit -m "fix: <description>"`
  - `git format-patch -1 HEAD -o artifacts/patches/`
- For bigger changes (e.g., adding tests, setting up lint, fixing build errors):
  - Push branch: `git push origin bug-review/auto/$(date +%Y%m%d%H%M%S)`
  - Open PR from branch with BUG_REPORT.md summary.

### 11. Reporting
- Generate BUG_REPORT.md in repository root with:
  - Summary: number of issues by severity (Critical, Major, Minor, Cosmetic, Suggestion)
  - For each bug: ID, Title, Severity, Affected area, Environment, Reproduction steps, Actual result, Expected result, Logs/stack trace, Screenshot, Suggested fix, Patch file reference.
  - Include links to artifacts and PRs if created.
  - Prioritize fixes: Blockers (build failures, critical security, runtime crashes), High (type errors, logic bugs), Medium (broken UI, missing tests), Low (lint/style, minor accessibility).
